최종 갱신: 2026-11-13 11:00 KST. 브랜치 `design/kitsch-diary`. push·배포 없음.

## 1. Objective

여행 생성 → 계획 → 오늘 → 돈·로컬 정산 → 성공 완료 확인·여권까지 로그인 없이 이어지는 흐름을 검증한다. 다시 여는 이유는 다음 일정·남은 돈·여행 완료 기록이다. Stage 1 완료 전 Stage 2에 착수하지 않는다.

## 2. Assumptions

- 시각 디자인은 소유자의 별도 작업이다. 기능·상태·연결만 수정하고 기존 공통 컴포넌트를 사용한다.
- 과거 보고서의 iCloud 차단 상태는 해소됐다. 원본 파일 읽기·타입 검사·전체 테스트·커밋이 현재 정상 동작한다.
- `837cde3` WIP 보존, `3b62376` 네 탭 기본 구현, `fa4ab46` 링크·개발 예시 여행은 기존 커밋이다. 재구현하지 않는다.
- `6aa0226` 폐기 잔재 정리 완료. 이후 아이콘 변경 커밋 `b917f65`는 병행 디자인 작업이며 기능 변경과 분리한다.

## 3. Recommended approach

실제 코드·테스트·시뮬레이터를 구분해 검증한다. 코드 존재만으로 완료로 표시하지 않는다. F-id의 이름은 역설계 원본 표에 맞춰 이전 보고서의 잘못된 분류를 수정했다.

## 5. User flow

빈 여행 이름은 저장하지 않는다. 여행 생성 직후 계획으로 이동한다. 여권은 귀국일 경과만으로 성공 완료를 추정하지 않는다. 귀국일 당일부터 사용자가 성공 완료를 확인해야 신규 도장을 발급한다. 취소 해제 후에도 다시 완료 확인이 필요하다.

## 6. Data / API design

- 여권 `passport:v1`에 `completed: string[]` 추가. 기존 `stamps`와 `cancelled` 및 여행·일기 DB는 그대로 보존한다.
- 이전 저장값에 완료 기록이 없으면 `completed: []`로 읽되 이미 발급된 도장은 보존한다. 신규 발급만 확인을 요구한다.
- 스탬프 ID는 `tripId:countryCode`. 귀국일은 여행 시간대로 판정하고 도장 날짜는 여행 종료일을 사용한다. 다른 여행에서 같은 국가를 방문하면 별도 도장이다.
- 여권 읽기 실패 시 쓰기를 차단하고 재시도를 제공한다. 완료·취소 저장 실패 시 오류를 보여 준다.
- 새 서버·로그인 의존성을 추가하지 않는다. JEV 핵심 파일·DB 마이그레이션은 수정하지 않는다.
